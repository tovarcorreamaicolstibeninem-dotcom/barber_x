Sistema de Gestión y Agendamiento de Citas

Plan de Aseguramiento de Calidad (PAC)

Proyecto
Sistema de Gestión y Agendamiento de Citas (ADSO)
Tecnologías
PHP, MySQL, HTML5, CSS3 y JavaScript
Estándar de referencia
ISO/IEC/IEEE 12207:2023 y Guía Metodológica CIES SENA

1. Introducción y contexto

En el desarrollo de aplicaciones web, la calidad del software no es un atributo accidental, sino el resultado directo de una planificación rigurosa, un diseño estructurado y una verificación sistemática. El presente Plan de Aseguramiento de Calidad (PAC) establece los criterios, metodologías y actividades orientadas a garantizar que el Sistema de Gestión y Agendamiento de Citas responda a los más altos estándares de desempeño, seguridad e integridad de datos.

El sistema abarca la automatización operativa de un establecimiento de servicios, permitiendo la interacción entre clientes, personal operativo (barberos/estilistas) y la administración central. La solución está construida sobre una arquitectura backend en PHP conectada a una base de datos relacional MySQL, complementada con interfaces web dinámicas.

2. Requisitos y alcance del PAC

2.1 Objetivos principales

  • Prevenir defectos operativos: Identificar inconsistencias en la lógica de negocio y restricciones de base de datos antes de la puesta en producción.
  • Garantizar integridad relacional: Asegurar que las entidades cliente, barbero, servicio, cita y cita_servicio mantengan consistencia total sin registros huérfanos ni duplicidades.
  • Validar seguridad web: Verificar que la aplicación sea resistente a vulnerabilidades comunes según OWASP Top 10, como inyección SQL, XSS y control de acceso deficiente.
  • Asegurar mantenibilidad del código: Promover convenciones de programación limpias y bien documentadas en PHP y MySQL para facilitar futuras expansiones.

2.2 Alcance del sistema

El PAC aplica a todos los módulos funcionales del sistema, cubriendo desde la capa de persistencia (modelo relacional de cinco entidades principales) hasta la capa de presentación (vistas HTML/CSS/JavaScript) y el procesamiento backend en PHP.

3. Arquitectura de datos objeto de evaluación

Para que las pruebas de aseguramiento de calidad sean efectivas, se evalúa directamente el modelo entidad-relación implementado en MySQL. Las entidades clave bajo monitoreo de calidad son:

  • Cliente: Almacena los datos personales y credenciales de los usuarios que solicitan los servicios.
  • Barbero: Contiene la información del personal técnico habilitado para prestar los servicios en el establecimiento.
  • Servicio: Catálogo de prestaciones disponibles con especificación de precio, duración y descripción.
  • Cita: Entidad transaccional que registra la fecha, hora, estado y vinculación entre un cliente y un barbero.
  • Cita_servicio: Tabla intermedia que permite la relación muchos a muchos entre citas y múltiples servicios solicitados en una misma sesión.

4. Requisitos y estándares de calidad

4.1 Requisitos funcionales y no funcionales

  • Funcionalidad: El sistema debe agendar citas calculando la disponibilidad horaria sin solapamientos entre barberos.
  • Seguridad: Autenticación basada en sesiones PHP seguras, contraseñas protegidas con password_hash y consultas preparadas (PDO o mysqli) contra inyecciones SQL.
  • Usabilidad: Interfaces intuitivas y adaptables (Responsive Design) con mensajes de validación claros para el usuario.
  • Rendimiento: Tiempos de respuesta inferiores a 2 segundos en la consulta y registro de agendamiento.

5. Matriz de pruebas y control de calidad (QC)

La siguiente matriz define las pruebas sobre los componentes fundamentales del sistema de agendamiento.

IDActividad / móduloProcedimiento de pruebaResultado / criterio esperado
PR-01Registro de entidades (cliente / barbero)Ingresar registros válidos desde el formulario web hacia MySQL.Persistencia correcta en las tablas cliente y barbero. Generación de claves primarias autógenas.
PR-02Validación de entradas (formularios)Intentar guardar campos obligatorios vacíos, correos sintácticamente inválidos o valores negativos.El sistema deniega el envío en cliente (JS) y servidor (PHP), mostrando un mensaje de error descriptivo.
PR-03Agendamiento transaccional (cita / cita_servicio)Crear una cita vinculando 1 cliente, 1 barbero y 2 o más servicios en cita_servicio.Inserción atómica (transacción MySQL); se genera el encabezado de cita y los detalles de servicios asociados correctamente.
PR-04Control de solapamiento (disponibilidad)Intentar agendar una cita para un barbero en una fecha/hora en la que ya tiene una cita confirmada.El backend detecta la colisión de horario y rechaza la reserva, protegiendo la agenda del barbero.
PR-05Control de accesos y roles (seguridad)Intentar acceder directamente a rutas de administración PHP sin sesión iniciada.Redirección inmediata al login y destrucción de sesiones no autorizadas (previene BOLA / Broken Access Control).
PR-06Integridad referencial (eliminación / edición)Intentar eliminar un cliente o servicio que ya posee citas asociadas.La base de datos restringe la acción mediante FK o aplica borrado lógico para evitar registros huérfanos.
PR-07Prueba de aceptación (usuario final)Simular el flujo completo: registro, inicio de sesión, selección de servicio/barbero y confirmación de cita.Flujo completado exitosamente sin errores de script PHP ni excepciones SQL visibles para el usuario.

6. Roles y responsabilidades en el PAC

  • Líder de proyecto / analista: Responsable de verificar la alineación entre las historias de usuario, la arquitectura de datos y los criterios de aceptación del PAC.
  • Desarrollador backend / frontend: Escribe código siguiendo estándares, ejecuta pruebas unitarias en PHP y soluciona inmediatamente los defectos reportados.
  • Responsable de pruebas (QA): Diseña las herramientas de pruebas, ejecuta la matriz de pruebas, documenta hallazgos y emite el dictamen de calidad.

7. Gestión de defectos y mejora continua

Cuando se detecta un fallo durante las pruebas, se sigue este ciclo de vida:

  1. Detección y registro: Documentar los pasos para reproducir el fallo, especificando el componente PHP o la consulta MySQL involucrada.
  2. Priorización: Clasificar el defecto como crítico (bloquea la operación), alto (falla de seguridad/integridad), medio o bajo (estético/usabilidad).
  3. Corrección: El desarrollador asignado aplica el parche en el código fuente o ajusta la estructura/script de la base de datos.
  4. Re-prueba (retesting): QA vuelve a ejecutar la prueba correspondiente y las pruebas de regresión para confirmar la solución.

8. Indicadores de calidad (KPIs)

Para evaluar de forma cuantitativa la efectividad del proceso de calidad, se monitorean los siguientes indicadores:

  • Porcentaje de pruebas exitosas: (Pruebas aprobadas / Total de pruebas ejecutadas) × 100 %. Meta: ≥ 95 % para liberación.
  • Densidad de defectos críticos: Número de errores graves pendientes por corregir. Meta: 0 antes de producción.
  • Tiempo promedio de cierre de defectos: Tiempo transcurrido desde el reporte de un fallo PHP/MySQL hasta su resolución y verificación.
